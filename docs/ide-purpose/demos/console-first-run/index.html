Design notes

1

One thing leads. The goal composer is the only elevated surface at rest — the single center of attention. Everything else (examples, import, preflight) is quiet chrome that supports it.

2

The interface explains itself. The entry point opens with "What are you building?" — the product vocabulary (surfaces) is introduced in one clause at the moment it's needed, not assumed.

3

The journey strip speaks in user outcomes. Describe → Review plan → Approve surfaces → Apps running. "Docker ready" is plumbing, not milestone #1 — it's demoted to a preflight status pill on the right, present but quiet.

4

Examples support, they don't lead. Clicking a card pre-fills the brief (try it). In the full product, cards open a pre-generated workspace, and the "Booking studio" card opens mid-flight — one surface live, one building — so the first thing a new user sees is the loop itself: goal → plan → running app.

5

Progressive disclosure. Description, Docker, Plan, Rules, Dev Loop, Brand, and Settings don't render at rest in an empty workspace — chrome has to earn its place. They appear when planning produces something to configure. The ghost line above marks where they'll land, so the layout doesn't reflow surprisingly.
